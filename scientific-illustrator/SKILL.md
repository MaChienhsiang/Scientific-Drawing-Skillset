# 科研绘图设计

## R — 原文 (Reading)

> 读者不读正文，十秒内就要看懂整个方法。所以写提示词的第一步不是描述画面，而是写剧本。
>
> — 整理稿第 6 条《MOSAIC Reasoning，顶会配图设计》

这份整理稿由多学科、多个期刊风格和多种 AI 工具的案例组成。它真正可迁移的内容不是某一套颜色、某一个模型或某个期刊的“固定画风”，而是一种工作方式：把科学逻辑压缩成可读的视觉叙事，再把叙事翻译成可执行的视觉规格，最后通过事实核对、缩略图检查、迭代和矢量化完成交付。

## I — 方法论骨架 (Interpretation)

科研图是论文的第二语言。它不应只是把名词画成图标，而应让读者沿着一条预设的阅读路径，在有限时间内理解一个主张、一个机制或一个系统关系。AI 的随机性只有在被视觉规格约束时才会变成生产力。

把任何主题转成科研图时，按五层组织设计：

1. **科学主张层**：用一句话写清图要证明什么；列出对象、关系、方向、条件、结果、证据和不确定性。
2. **视觉剧本层**：指定读者先看哪里、后看哪里；把机制写成起点、转折、验证、结果或反馈闭环，而不是元素清单。
3. **信息架构层**：选择单场景、流程、分层架构、对比、空间地图、中心放大或多面板；为面板、比例、留白和连接关系分配位置。
4. **视觉语法层**：给颜色、线型、箭头、轮廓、字体、图标和细节密度分配稳定的语义；同一语义在全图保持同色、同线型、同方向。
5. **生成与验证层**：用正向规格和负向约束生成初稿，把结构、风格、细节分开迭代；检查科学事实、可读性、色盲/印刷表现、缩略图和编辑性。

核心原则：

- 先写“要传达的关系”，再写“要出现的物体”。
- 用比例、位置、线宽、颜色和数量表达要求，不只使用“高级、专业、好看”等形容词。
- 颜色是语义编码，不是装饰；箭头是关系和时间的语法，不是填空线。
- 信息层级决定视觉层级。次要结构变淡，关键机制获得更高对比度和更大的空间。
- 参考期刊或优秀图片时，只提取可观察的视觉特征（背景、网格、色域、线条、标注密度、视角、留白），不把期刊名称当成质量保证，也不要求逐像素复制。
- AI 生成的栅格图是结构草稿。论文最终交付应优先保留可编辑的文字、箭头、面板和图例对象。

## A1 — 应用示例 (Application Example)

### 示例 1：计算机方法综述图

- **类型与来源**：原文案例，整理稿第 6 条。
- **问题/输入**：说明一种“依赖图—调度—并行处理—验证—局部修复—答案”的推理方法。
- **方法论的使用**：先写七个节拍，再为依赖、调度、候选、验证、错误分别规定颜色和箭头；把验证器设为主流程中的门，而不是孤立模块。
- **结果**：读者可沿着问题到答案的顺序理解方法，并能在缩略图下辨认已验证块和错误回路。

### 示例 2：跨尺度环境过程图

- **类型与来源**：原文案例，整理稿第 2 条。
- **问题/输入**：从地下或源区开始，展示上升、传输、沉降、影响和恢复的级联过程。
- **方法论的使用**：用空间方向承载时间方向，将地下、地表、高空和下游分区；用单一强调色标记源头或风险，其余使用低饱和中性色。
- **结果**：图从左到右形成闭环，避免只画“一个很像火山/污染源的物体”而没有因果链。

### 示例 3：生物医学机制图

- **类型与来源**：原文案例，整理稿第 5、55、89 条。
- **问题/输入**：表达药物、细胞、微环境、受体和免疫反应之间的关系。
- **方法论的使用**：先锁定受体位置、细胞形态、药物路径和激活方向，再决定是否使用局部放大；将医学事实核对交给领域专家，不让模型补造解剖或分子细节。
- **结果**：图的审美服务于机制准确性，颜色和轮廓帮助读者区分细胞类型，而不是制造“漂亮但错误”的组织图。

### 示例 4：从栅格草图到可编辑交付

- **类型与来源**：原文案例，整理稿第 4、83、85 条。
- **问题/输入**：需要将 AI 初稿用于论文、海报或报告，并继续修改标签、颜色、线宽和位置。
- **方法论的使用**：生成阶段保持简洁结构和高分辨率；随后重建或矢量化模块、路径、文字和图例；对文字密集部分优先在矢量编辑器中重排。
- **结果**：得到可缩放、可修改、可检查的 SVG、Visio、Illustrator 或其他编辑格式，而不是把 PNG 当作终稿。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill？

1. “把这段方法画成论文 Figure 1 / graphical abstract / 技术路线图。”
2. “帮我给 Nano Banana、Midjourney、Gemini 或其他模型写科研绘图 prompt。”
3. “我的图看起来像 PPT、像宣传册、信息太乱，怎么改？”
4. “参考某个期刊/子刊的图，换成我的研究主题。”
5. “这张 AI 图如何变成可编辑 SVG/Visio，并保证标签和箭头能继续改？”
6. “我有一张生物、材料、能源、地学、建筑、计算机或医学机制图，帮我做结构和科学性审查。”

### 语言信号

- “科研绘图”“示意图”“机制图”“综述图”“graphical abstract”“Figure 1”
- “像 Nature/Nature Reviews/NEJM/Joule，但换成我的主题”
- “提示词要具体”“要有负面约束”“要能缩略图看懂”
- “AI 生成后转 SVG / Visio / Illustrator”“可编辑”“矢量化”
- “配色要统一”“箭头表达流程”“留白”“面板”“放大框”“信息层级”

### 与相邻能力的区分

- **与统计绘图的区别**：本 skill 处理科学叙事、机制、系统和空间关系；若任务核心是从真实数据计算柱状图、置信区间或显著性，应先使用统计绘图流程，不能让生成模型臆造数据。
- **与纯图像生成的区别**：本 skill 要求先锁定科学事实和信息架构；“生成一张好看的科技插画”但没有科学关系时不应套用完整流程。
- **与排版软件操作的区别**：本 skill 产出可编辑结构和交付计划；具体软件的快捷键、插件和导出参数按用户环境另行处理。

## E — 可执行步骤 (Execution)

**必需输入**：主题或论文片段；图的用途（论文、综述、海报、汇报、教学）；目标读者；希望表达的主张或机制；可用的参考图（可选）；输出比例/格式和是否需要可编辑。缺失主张、关键对象或定量数据时先列出缺口，不替用户猜测。

**交付物与完成标准**：

1. 一句话科学主张和阅读顺序。
2. 事实/关系清单（对象、位置、方向、条件、结果、单位、证据、禁止臆造项）。
3. 文字版 storyboard（面板、比例、动线、必需元素、可删元素）。
4. 正向 prompt 与负向约束；必要时给出适合不同模型的短版和长版。
5. 质检清单和迭代建议。
6. 若用户需要，给出可编辑 SVG/Visio/Illustrator 的对象分层与矢量化方案。

### 步骤 1：判定图型和交付场景

从以下图型中选一个主型，必要时组合：机制/因果图、流程/闭环图、系统架构图、空间/地图/地形图、宏观—微观多面板图、方法对比图、临床/解剖图、真实数据叠加图、概念化叙事图。记录画布比例、最终尺寸、目标缩放、是否需要文字和是否需要编辑。

完成标准：主型能解释为什么采用这种布局；如果只能说“做一张高级图”，停止生成并补齐用途和主张。

### 步骤 2：建立科学事实锁和主张句

把输入拆成以下表格，再开始构图：

| 字段 | 内容 |
|---|---|
| 主张 | 这张图要让读者相信或理解的一句话 |
| 对象 | 必须出现的实体、状态、过程、数据或边界 |
| 关系 | 因果、流向、依赖、对比、层级、空间邻接或时间顺序 |
| 方向 | 箭头起点、终点、正反方向、循环条件 |
| 条件与单位 | 温度、尺度、时间、剂量、频率、地理范围等 |
| 证据 | 论文、实验、数据、规范或用户提供的事实 |
| 禁止臆造 | 不确定的结构、数字、标签、结果和品牌元素 |

对于定量数据，要求用户提供原始值或真实图表；生成模型只能负责视觉包装，不能代写实验结果、显著性、坐标数值或统计结论。

完成标准：每条主箭头都能在事实表中找到来源；无法确认的内容标为“待核查”，不得通过视觉暗示伪造确定性。

### 步骤 3：写视觉剧本和信息层级

用“起点 → 转换/机制 → 检查或分叉 → 结果/应用 → 反馈或边界”写阅读路径。若是空间过程，用“源区 → 传播 → 受体/影响 → 恢复或控制”；若是方法综述，用“问题 → 基线缺陷 → 关键模块 → 验证 → 贡献 → 失败边界”。

为每个元素分级：

- **一级**：主张、主流程、核心对象；最大或最高对比度。
- **二级**：支持机制、辅助模块、局部放大；中等饱和度和线宽。
- **三级**：装饰、背景、比例尺、次要设备；低对比度，不能抢主叙事。

完成标准：读者在 10–30 秒内能复述主张和主要动线；删掉任何三级元素后，主论证仍完整。

### 步骤 4：选择版式和尺寸预算

按信息关系选择版式，而不是套固定模板：

- **单场景/连续剖面**：适合空间和环境级联，使用统一视角与一条主动线。
- **横向流程/闭环**：适合工艺、算法、供应链、实验步骤；循环箭头必须标出循环条件。
- **分层架构**：适合系统、模型、设备；层间连接要标明数据、能量、物质或控制关系。
- **多面板**：适合宏观到微观、基线到改进、现象到机制；面板要互相引用，避免四块孤岛。
- **中心主体 + 环绕模块**：适合核心设备、组织、平台或单一技术与应用场景。
- **地图/地形/等轴空间**：适合地理、城市、建筑、基础设施；空间尺度、方向和图例必须真实或明确抽象化。

写出面板占比、留白比例、阅读方向、元素最大数量和标签位置。多面板不要默认等宽等高；比例应服务论证。

完成标准：每个面板有唯一职责，连接线不会穿过无关内容；缩小到目标栏宽后，一级元素和主箭头仍可辨识。

### 步骤 5：建立视觉语法

先定义语义映射，再挑具体颜色。一个可用的起点是：主结构用冷灰/蓝灰，输入或候选用蓝，控制/路由用橙，证据或外部工具用紫/青，已验证或结果用薄荷绿，错误/风险用珊瑚红；随后根据学科和色盲/印刷要求调整。颜色只是示例，不能把这套映射当成跨学科硬规则。

同时定义：

- 背景、边框、主线和次线的色值或明度范围；
- 实线/虚线/双向线/曲线各自表达什么；
- 箭头方向、粗细、端点和是否允许交叉；
- 字体类别、层级、最小字号、标签长度和上下标规则；
- 图标、细胞、设备、地形或人物是否采用扁平、2.5D、等轴、剖面或真实纹理；
- 留白、阴影、渐变、纹理和装饰的上限。

完成标准：读者不看图例也能从重复的颜色/线型推断至少一部分关系；同一语义没有两套视觉编码。

### 步骤 6：把规格写成 prompt

按以下顺序写 prompt，必要时再翻译成模型更擅长的语言：

1. **任务与主张**：图要解释什么，给谁看，最终用于什么。
2. **构图与阅读顺序**：画布比例、视角、面板、占比、动线和留白。
3. **科学对象与关系**：每个区域的必需对象、状态、动作、输入输出和空间位置。
4. **视觉语法**：色彩语义、线型、箭头、字体、图标、细节和材质。
5. **文本策略**：必须出现的短标签、公式或符号；如果模型文字不可靠，明确“留出文字区域，后期叠加”。
6. **负面约束**：禁止额外面板、重复对象、错误方向、伪造数字、无关品牌/水印、深色背景、过度渐变、霓虹、玻璃拟态、电影光效、卡通化、拥挤标签或不可读小字等。
7. **输出约束**：比例、分辨率、背景透明/白底、是否需要单独导出面板，以及后期编辑格式。

避免只写“顶刊风格”“专业”“高级”。把它们翻译成可检查的参数。也不要迷信“prompt 越长越好”：长度应服务于未解决的科学和布局约束，重复形容词只会稀释优先级。

### 步骤 7：分阶段生成和迭代

至少分三轮：

1. **结构轮**：只检查主张、版式、面板和动线，暂不追求细节。
2. **语法轮**：加入色彩映射、箭头、标注、视角和材质，检查全局一致性。
3. **事实轮**：逐项核对对象、方向、单位、受体位置、化学式、解剖结构、设备连接和边界条件。

每轮只改一类问题，把“观察到的问题 → 违反的规格 → 下一轮修改指令”写成反馈。保存成功 prompt、参考图、版本和失败原因，形成可复用模板。

### 步骤 8：验收与可编辑交付

使用以下检查：

- **科学性**：主张、因果、方向、尺度、单位、结构和术语没有被模型改变。
- **叙事性**：不看正文也能找到起点、主路径、结果和限制；没有无主线的元素堆砌。
- **可读性**：目标尺寸和缩略图下，一级标签、箭头、图例和关键对比仍清楚。
- **视觉一致性**：颜色、线宽、圆角、阴影、视角、字体和图标风格贯穿全图。
- **可访问性**：不只依赖红/绿区分；必要时增加线型、纹理、形状或文字；考虑灰度打印。
- **合规性**：无水印、无虚构品牌、无不必要期刊标志；参考图只用于学习视觉特征。
- **编辑性**：文字、箭头、图例、面板和关键对象可单独选择和修改；复杂栅格背景不应掩盖关键科学信息。

需要矢量交付时，优先在源头保持简洁色块、清晰边界和高分辨率；再将对象重建或矢量化为 SVG/PDF/Visio/Illustrator 图层。矢量化后的路径数、文字识别和渐变分层要人工抽查，过度复杂的自动路径应简化。

## 可选联合接口 — PromptPack / FigureSpec v1

可单独使用：若没有上游规格，先提取 `claim`、`objects`、`relations`、`reading_path`、`layout` 和 `unknowns`；缺少事实时输出占位 Prompt，不自行补全结构、数据或机制。

接收 `scientific-figure` 的 `FigureSpec + LayoutSpec` 时，必须保留其 `claim`、`panels`、`grid`、`reading_path`、`typography` 和 `publication`，只增加：

```yaml
prompt_pack:
  positive_prompt: "结构、对象、关系、视角和视觉语法"
  negative_constraints: ["错误方向、伪造标签、品牌、水印、商业装饰"]
  generation_rounds: ["structure", "visual-grammar", "fact-check"]
  editable_plan: "文字、箭头、面板、图例和对象的图层计划"
  rendered_unknowns: ["模型仍未可靠表达的内容"]
```

联合使用时，生成或重建完成后，将 `prompt_pack`、渲染预览、编辑图层和 `rendered_unknowns` 交回 `scientific-figure` 做版面与出版检查；若图中包含真实数据，数据图层必须由 scientific-plot 或统计绘图工具生成，不能由图像模型绘制数值。单独使用时直接完成事实锁、故事板、Prompt、迭代和可编辑交付，不要求上游技能存在。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 用户只需要艺术海报、头像、装饰插画，没有需要解释的科学关系。
- 用户要求生成真实实验数据、统计显著性、坐标值、病例结论或论文结果；应要求真实数据并使用统计/绘图工具。
- 关键事实、结构或机制尚未确定，却要求直接生成“最终稿”；先转为事实核查和 storyboard 任务。
- 任务只是学习某个软件的快捷键、脚本 API 或导出故障；使用对应工具技能。

### 整理稿中的失败模式

- 把“画一张科研配图”当作完整 prompt，导致模型自行发明构图和审美。
- 只堆对象，不写主张、阅读顺序和关系，生成“名词图鉴”。
- 只写“像 Nature/顶会”，不拆解色彩、留白、线条、字体和信息层级。
- 过度依赖渐变、阴影、3D、电影光效或过饱和色彩，牺牲打印和缩略图可读性。
- 多面板互相孤立，或使用等宽四列把复杂关系压扁。
- 让 AI 直接渲染大量论文文字、化学式、统计数字或小标签，却不做后期校正。
- 把第一张生成图当成终稿，跳过专家核对、负面约束、版本反馈和可编辑化。
- 把某个工具、网站或期刊风格的个案宣传当成普遍保证；效果取决于输入事实、任务类型和验证。

### 重要限制

整理稿主要来自社交媒体案例，展示的是可迁移的设计经验，不是各期刊的正式投稿规范，也没有证明每个工具或每个 prompt 在所有模型上稳定有效。涉及医学、化学、材料、工程安全、地理尺度和定量数据时，必须由领域专家或原始数据做最终审核。
